About

I'm a Control and Automation Engineer pursuing my M.Sc. at Yıldız Technical University. My core interest is the sim-to-real pipeline — the engineering discipline of ensuring that a system modeled mathematically actually behaves correctly when running on physical silicon under real-world conditions.

My approach follows the V-model rigorously: I design and tune complex control logic in MATLAB/Simulink, validate through MIL and SIL testing, then implement the verified algorithms as production-grade bare-metal C on STM32 platforms with a strict layered architecture (BSP → Middleware → Application). I enforce MISRA-C standards and use logic analyzers for hardware-level debugging.

I interned at Baykar Technologies in the Control, Guidance & Navigation team, working on EKF-based battery state estimation and observer-based fault detection for UAV systems. At ECEMTAG CONTROL TECHNOLOGIES I also developed transmission ECU Model Based algorithms — gear shift logic and unit tests — on a defense platform under NDA.

Outside of formal work, I co-founded RoboHexa, an independent project to rebuild the hexapod firmware from scratch as a professional-grade, MISRA-compliant codebase — transforming university prototyping code into something deployable.

"A beautiful controller that can't run on hardware is just theory. Firmware without a proper model is just guessing. The job is closing the gap between the two — and doing it in a way that can be validated, not just hoped."

Engineering Approach

The core engineering challenge was sim-to-real transfer: getting a 18-DOF system with compliant actuators (MG996R servos) to walk stably on uneven terrain without discovering algorithm failures on hardware. The solution was a rigorous SIL pipeline using Simulink C Caller blocks — the actual embedded C algorithms were executed inside the simulation model, meaning every bug caught was a real embedded bug, not a behavioral approximation.

  • Rigid-body physics model built in Simscape Multibody including MG996R actuator dynamics and MPU6050 IMU modeling
  • Custom Inverse Kinematics solver validated in simulation joint limits enforced analytically before hardware deployment
  • SIL via Simulink C Caller: embedded C code executed in-loop against physics model not behavioral approximation
  • Three gait modes implemented: tripod(fastest), wave(most stable), ripple(compromise) selectable via RF remote
  • Real-time roll/pitch estimation: complementary accel+gyro fusion → PID body-level stabilization loop
  • Microswitch tactile feedback on each foot — state machine adjusts step trajectory on unexpected ground contact
What SIL Actually Caught
  • Joint limit violations — kinematics computed angles outside servo physical range; would have stripped gears on hardware
  • Gait timing / coordination failures — phase offsets between legs caused simulated body rotation before physical testing
  • Coordinate frame sign errors — axis inversions in the IK solution; silent on hardware until the leg moves the wrong direction
  • Unstable PID parameters — control gains that caused oscillation in the physics model were corrected before deployment
  • Sensor noise sensitivity — roll/pitch estimate degradation under high-frequency vibration modeled and filtered in simulation
Verified Outcome
  • Walks continuously on flat terrain and uneven surfaces up to 30° slopes
  • Step height configurable via RF remote — adapts to terrain in real time
  • Zero hardware failures attributed to algorithm errors post-SIL validation

Architecture & Design Decisions

A complete flight controller in hand-written bare-metal C on STM32F4 — no HAL abstraction for the IMU interface, no RTOS, no library flight stack. Every layer was designed from first principles: register-level SPI driver, 6-State ESEKF, and a cascaded PID attitude controller. The architecture uses strict layer separation: BSP → Middleware (EKF math) → Application (control loops).

  • ESEKF State Vectors — Nominal: [q_w, q_x, q_y, q_z, b_gx, b_gy, b_gz]; Error-state (6-dim): [δθ_x, δθ_y, δθ_z, δb_gx, δb_gy, δb_gz]. Error-state formulation chosen to avoid quaternion covariance singularities and reduce linearization error at high angular rates
  • 1 kHz loop driven by ICM-20948 data_ready interrupt SPI read
  • Online gyro bias estimation — b_g states updated continuously via process noise Q matrix; filter accuracy improves as sensor thermalizes during operation
  • Cascaded control: 1 kHz inner angular-rate loop + 250 Hz outer attitude angle loop
Technical Highlights
  • Implemented an ICM-20948 driver over SPI, including register configuration, data acquisition, and transaction management.
  • Hard & soft-iron magnetometer calibration completed; cross-axis interference eliminated by ensuring normalized accel/mag vectors before the ESEKF update step
Current Status & Next Steps
  • 9-axis ESEKF attitude estimation bench-validated; stable quaternion output confirmed across roll, pitch, yaw axes
  • Closed-loop: EKF angles feeding PID controllers driving motors — tested statically on bench
  • Next: custom PCB designed and printed → outdoor PID tuning for stable flight

System Architecture

A high-fidelity 6-DoF quadcopter simulation with a fault detection system. motor failures detected and classified using only model-based residuals. Developed within Baykar's CNS team.

  • Full 6-DOF model: cascade control from position setpoint → attitude → angular rate → individual motor commands
  • Observer-based FDD: model predicts expected system output; deviation between prediction and simulation output generates residuals
  • Residual projection + isolation logic maps residual signatures to specific motors. uses the characteristic signature matrix (M1: [+,–], M2: [–,–], M3: [–,+], M4: [+,+])
  • Fault classification: partial thrust loss (propeller damage, ESC degradation, motor wear) — primary fault mode by design
Validation & Results
  • Detection latency 100–300 ms: intentional trade-off — faster threshold = noisier; current setting optimized for reliability over speed
  • False positive rate <5% under gyro-noise simulation and step torque disturbances (wind gust injection)
  • 100% correct motor identification across all four motors under partial under-thrust faults tested independently
  • Observer remained stable under all tested conditions — no divergence with tuned gains
  • Clear residual separation verified: healthy-state residual ≈ 0; faulty-state residual deviates significantly above threshold
Design Scope & Honesty
  • Simulation study — not deployed to physical hardware
  • Over-thrust faults excluded by design (symmetry ambiguity in residual signatures)
  • Sensor faults not in scope for this implementation

Model Architecture

A cell-level LiPo battery model built around a first-order Thevenin (1RC) equivalent circuit — chosen for real-time suitability without sacrificing the dominant dynamics. The model goes beyond basic OCV by including hysteresis-aware OCV (critical accuracy improvement at mid-SoC), temperature-dependent resistance, thermal coupling between cells, and a capacity degradation model.

  • 1RC Thevenin: OCV(SoC,T) + series resistance R0 + one RC branch for transient response — computationally lean for EKF state propagation
  • Hysteresis-aware OCV: standard OCV curves are flat at mid-SoC — hysteresis model significantly improves estimation accuracy in this critical region
  • 2D lookup tables for temperature/SoC dependencies — EKF operates with temperature-corrected parameters at every timestep
  • Per-cell SoC tracking with cell imbalance detection — individual cell degradation visible, not just pack-level voltage
EKF Design & Validation
  • EKF corrects coulomb counting drift using voltage feedback — ground-truth SoC computed by numerical integration of current (reference coulomb counter); EKF SoC compared against this reference to measure estimation error
  • ~1.2% RMS error achieved under constant-current discharge profiles (2.2A baseline); worst-case ~4–5% during high-current transients (>10C) due to flat OCV region dynamics
  • Validated across 0–40°C with temperature-corrected resistance and capacity parameters
  • Tested at C-rates from near-zero (hover/cruise) to ~10C (aggressive maneuver spikes)
SoH & Fault Detection
  • SoH modeled via Arrhenius + current-throughput degradation model (~±5–10% qualitative accuracy) — online EKF SoH estimation not implemented; acknowledged as a future extension
  • Fault detection algorithms for cell voltage imbalance and voltage sensor drift implemented and validated
